# hscredit 后续功能优化方案

> 实施范围已按用户后续指令收敛。下文保留为历史方案，不能据此实施额外模型报告章节、Vintage 成熟度、置信区间等被拒绝内容。当前采用的报告口径、API 与资源部署方式见 `docs/articles/report-resources-deployment.md`；资源和部署治理已获明确实施授权。

制定日期：2026 年 11 月 4 日。基线：`0.1.3` / `bab104b19216309f10ed09184888aa69dac30ff5`。

这版方案根据当前实现和本次可复现问题独立制定，没有继承已有规划。总体目标是让同一数据通过不同公共入口得到相同业务结论，让每份报告可追溯到样本、标签、权重、分箱和模型版本，并让大数据流程具有可说明的资源边界。

配套分析见 `2026-11-04-capability-audit.md`，F01—F12 为该报告的问题编号。这是一份实施方案，本次交付未修改生产代码、默认行为或版本号。

## 交付顺序

```mermaid
flowchart LR
    A[批次一 修复结果语义与输入验证] --> B[批次二 贯通验证协议与报告结果]
    B --> C[批次三 补齐评估与策略决策报告]
    B --> D[批次四 端到端资源和部署治理]
    C --> E[批次五 按业务需求扩展能力]
    D --> E
```

依赖关系比日历日期更重要。工作量使用 S/M/L 表示相对规模：S 是局部修复，M 涉及多个公共入口，L 涉及跨模块契约或格式迁移。它们不代表已承诺工期。先完成正确性验收，再确定下一批范围；性能优化和 API 调整均不得绕过语义验收。

| 批次 | 目标 | 交付物 | 退出条件 |
| --- | --- | --- | --- |
| 一 | 消除已确认的计算歧义、未消费参数和支持范围内兼容失败 | 兼容修复、最小复现回归测试、行为说明 | F01/F02/F03/F04/F09/F10/F12 有明确修复或拒绝路径 |
| 二 | 保证划分、监督变换和报告交付遵守同一协议 | 划分审计、推荐工作流、结果 schema、JSON 输出 | 分组/时间隔离可验证；失败状态不在默认链路丢失；机器结果可往返 |
| 三 | 报告支持独立评估和策略取舍 | 概率质量、区间估计、客群/时间、策略比较章节 | 每个结论具有口径、样本量、评估角色及必要假设 |

## 批次一 修复结果语义与输入验证

### A00 修复支持版本范围内的已复现兼容失败

**P1，M，来源 F12。** 先处理 LightGBM 3.3.5 的回调属性赋值和 None 学习曲线路径，补旧版及新版工作流测试。版本下限是否调整要由实际验证决定，不能直接假设“装最新即可”。

对本次 29 个失败节点分别保留兼容缺陷、缺失依赖和绘图样式的归因；8 个 Net 用例在复查环境跳过，不作为修复完成。先建立符合声明依赖的环境，再验证整个相应功能组。

验收：支持范围内的自定义损失、指定指标早停、调参后报告流程通过；缺失学习曲线产生明确空结果或状态；旧版与新版有独立安装测试，构建后的依赖声明与测试矩阵一致。

### A01 统一标签缺失与灰样本语义

**P1，M，来源 F01。** 复用 `utils.data_contracts`、`utils.targets`，把缺失标签和业务灰样本定义分离。模型、编码器、筛选器、报告分别可接受不同任务类型，但不能因标签传法改变其有效样本含义。

实施内容：

- 为标签归一化结果保留原始行位置、有效掩码、缺失和剔除原因；多标签各自保留掩码。
- 增加明确的缺失标签策略；不把“不成熟”和“没有标签”自动转换为好样本。
- 统一显式 y、target 列、Series、数组和 callable 的对齐说明。明确位置对齐和索引对齐，不自动取索引交集。
- 用入口兼容层承接旧 `del_grey=False` 的非 1 归零行为；新推荐工作流采用明确的安全策略。

验收：同一标签的所有等价传法具有相同有效位置、分母、坏率、AUC/KS、分箱统计和权重筛选。覆盖乱序/重复索引、缺失、非法标签、全灰、单类、多标签不同成熟度。将报告中 5 行标签例子固定为语义回归样例。

### A02 明确校准参数和权重的去向

**P1，M，来源 F02。** 概率校准分为“基础模型训练”和“校准拟合”，分别定义可消费参数；复用现有样本参数切片工具。

- 对不重训基础模型的模式，拒绝未消费的基础训练参数。
- 给支持权重的校准算法透传并验证权重；没有实现权重的算法显式报错。
- 内部分割时，基础模型和校准器分别取得各自样本位置对应的参数。训练权重与独立评估权重继续分开。
- `calib_metrics_` 标记为校准拟合内统计；独立评估记录评估数据角色，不覆盖拟合内记录。

验收：极端正类权重会按预期改变映射；整数频数权重与重复样本拟合在算法允许的误差内一致；负权重、长度错误和拼错参数失败；calib_ratio 模式的两部分权重位置正确；序列化前后预测相同。

### A03 让报告的权重和金额口径可见

**P1，L，来源 F03。** 先修复无声明混用，再扩展加权统计。

- 内部区分件数、频数权重、成本权重、金额；不能笼统将金额解释为任何 sample_weight。
- 总体、分箱、分群、分月和策略表共享有效样本及明确统计口径。
- 如果某章节暂不支持当前权重，选择显式件数对照表并标注，或者在严格模式拒绝；禁止输出同名但不同含义的坏率。
- PSI 默认件数分布时明示该口径。是否增加加权 PSI，作为独立能力实现并验证，不简单把现有 PSI 改成权重分布。

验收：本次 200 行样例不再出现无说明的 `0.909708` 与 `0.335` 并列；分箱分子/分母合计与总体相等；零权重、金额缺失、筛选后零有效权重有清楚处理；无权重历史结果不变。

### A04 冻结跨数据集分箱基准

**P1，M，来源 F04。** 复用已有 `BinSpec`、binner 和 `MonitoringBaseline`，增加报告分箱参考策略。

- 训练集或指定基准集拟合一次，验证/OOT/时间/客群只 transform。
- 保留每数据集独立分位箱，命名为独立排序分析，报告中显式标识。
- 基准与目标标签解耦，监控窗口不能用其真实标签重拟合边界。
- 结果携带分箱版本、数值精度、闭区间语义、未知/缺失策略；展示小数位不改变执行边界。

验收：评分范围整体平移后，冻结边界仍完全一致且箱占比会变化；缺失、边界值、极值、未知类别得到稳定箱号；分类/回归报告遵循同一参考策略；跨数据集缓存不会串用。

### A05 在报告启动前验证明确请求

**P1/P2，S，来源 F09/F10。** 统一检查 features、target、date、group、amount、权重列和预测输出。

- 显式指定但不存在的字段报错；未指定的可选字段才允许跳过。
- 概率校验范围、类别数、类别列映射及必要的归一性；分数和 margin 使用独立输出类型。
- 用户自定义预测方法需要声明输出语义，不能只根据方法名推断所有条件。

验收：拼错金额列不再返回件数表；`predict_proba` 的负值或大于 1 的值被拒绝；合法概率、合法分数、反向安全分和自定义预测保持可用；错误指出字段/数据集/输出类型。

## 批次二 贯通验证协议与报告结果

### B01 增加可审计的划分协议

**P1，M，来源 F05。** 保留现有 time/oot/group split 工具与自定义 splitter 支持，在其上增加划分验证与结果记录。

- `groups` 与整数 cv 组合必须实际分组或明确拒绝；单次留出和多折行为一致。
- 支持时间、实体、观察窗口三个独立约束：训练时间不越界、实体不跨隔离组、标签在训练截止时已成熟。
- 以时间长度表达 gap/embargo 的新接口，与现有按行 gap 明确区分。
- 记录训练/验证位置、时间范围、实体重叠数、标签覆盖率及哈希；预计算划分可用于复现，不需保留客户明文身份。

验收：20 客户样例的每折实体交集为 0 或调用明确失败；重复时间戳、缺失实体、乱序时间、时间+实体混合场景有确定行为；报告能说明选模使用哪个验证集，OOT 不被并入选模。

### B02 建立完整预处理参与交叉验证的推荐工作流

**P1，M，来源 F06。** 主要交付物是可靠的组合入口与 Notebook，不再创造一套与 sklearn Pipeline 平行的估计器体系。

- 在每个训练折内拟合监督分箱、监督编码、筛选和模型；折外只使用训练折产物。
- Target 等有 OOF 能力的编码器在推荐流程显式启用；保留旧 in_sample 接口并说明适用范围。
- 对完整 ID、高基数标签编码、先全量筛选后交叉验证等模式给出针对性诊断。
- 时间 OOF 未覆盖区间保留覆盖掩码，不悄悄回填样本内编码；允许用户选择丢弃起始窗口或指定可说明的先验。
- 校准使用独立校准集或可信 OOF 概率，最终测试集仅评估。

验收：唯一 ID 不能在标准工作流获得虚假的独立验证优势；改变验证标签不会改变训练折分箱/编码；Pipeline 与手工正确流程一致；多次运行固定种子可复现；Notebook 在干净环境可执行。

### B03 完整保留报告状态并提供机器接口

**P1/P2，M，来源 F07/F08/F11。** 在现有 `ReportResult` 上扩展，避免新增不兼容的第二套结果类。

- 新推荐入口直接返回兼容 dict 的结构化结果。旧纯 dict/tuple/路径接口保留适配器。
- 每章节包括状态、原因、输入/有效/输出行数、口径、耗时和基准版本。未请求与执行失败使用不同状态。
- 定义版本化 JSON schema：表格显式包含 columns、index、records、types、metadata；MultiIndex 和缺失值具有可逆表示。
- 总览可选择实际选模和业务指标，固定四指标摘要作为兼容模板。
- 计算、渲染、发布职责分开；严格发布验证章节，不依赖日志判断成功。

验收：默认 EDA→Excel 流程保留失败状态；JSON 可在严格 `allow_nan=False` 模式输出并还原表结构；中文列、多层列、时间值和空表可往返；损坏/失败章节不会被误标为成功；已有消费者通过兼容测试。

### B04 收敛公共 API 说明和兼容清单

**P2，M。** 以本次 511 个顶层导出及懒加载入口为初始清单，自动生成文档和测试参数。

- 为 estimator、calibrator、scorecard、rule、report、database adapter 建立能力表。
- 明确 fit 返回值、预测语义、权重角色、目标对齐、缺失策略、原生/通用保存格式。
- 给行为差异提供便捷适配层，不批量改名，也不将 Tuner.fit 的旧字典返回值直接改成 self。
- 同步 AGENTS/安装指南/Notebook 中不存在的 extras 与过时入口。

验收：文档的导入、签名和示例由测试校验；发现 API 遗失时定位具体模块；deprecated 路径有替代项和迁移说明；无意新增公共符号也能被发现。

## 批次三 增强评估与策略决策报告

### C01 增加样本与评估口径总表

**P1，M，依赖 A01/A03/B01。** 将已经分散在模型报告、标签定义和 Vintage 中的信息整合为通用评估上下文。

内容包括样本粒度、重复实体策略、观察起止、标签窗口、数据角色、有效/缺失/未成熟/灰样本数、正类定义、风险方向、权重角色、分箱版本、模型版本。每个派生指标关联该上下文。

验收：总体与每个子群的分子分母可重算；多标签不共享错误分母；未成熟样本改变只影响对应目标；状态表、图注和 JSON 口径一致。

### C02 提供核心性能指标和模型差异区间

**P2，M，依赖 B01/B03。** 在已有点估计之外，增加 AUC、KS、TopK 捕获及业务指标的区间估计；支持按样本、客户和时间块的抽样单位。

模型比较使用同一评估样本的配对重采样，输出差值区间、样本量、有效重采样次数及失败原因。保留原始指标方向，不能用取绝对值掩盖方向错误。小样本或单类结果显示不可估计及原因。

验收：固定种子可复现；相同模型的配对差值为 0；按客户重复采样保持客户内所有记录共同出现；费用与训练/绘图并行共享预算；结果不能暗示统计显著即代表业务收益。

### C03 形成独立概率质量报告

**P2，M，依赖 A02/A03。** 复用现有四种校准器与可靠性图，增加独立数据上的 Brier、LogLoss、ECE、分箱样本量、校准前后对照、时间/客群分层。

报告分别显示“校准拟合内”“验证”“最终测试”，明确基准和加权方式，给出分箱策略及缺失单元。模型选择先确定指标再调参，避免看到所有结果后追选最有利指标。

验收：用独立概率模型和可控失准数据核对结果；同一预测经统一评估器与报告计算得到相同值；校准训练集不被自动称为测试集；零概率和单类子群有明确数值处理。

### C04 以相同约束比较策略

**P2，L，依赖 A03/A04/B03。** 扩展已有 threshold、Swap、规则报告和利润指标，不重复建设规则引擎。

- 支持固定审批率、固定拒绝率、固定人工审核容量和固定风险预算下的并列结果。
- 区分人数、件数、金额、预估损失和收益假设；参数进入报告。
- 展示边界同分处理、阈值敏感性、分群差异及时间稳定性。
- 对由参考客群外推的风险结果标注外推来源和条件，避免把估计值误认为实际观测。

验收：同一规则集合的串行/并行执行得到同样决策集合；对比策略使用同一母体及标签窗口；预算边界可逐行核验；金额结果可用独立汇总公式复核。

### C05 完成多标签与监控结果整合

**P2，M，依赖 A04/C01。** 模型分月报告扩展为按所选标签分别计算，并与 MonitoringBaseline 共享冻结基准。

输出各窗口样本量、有效标签、未知类别、缺失率、分布漂移、核心性能和基准标识；告警先区分数据缺失、标签延迟和实际模型退化。已有 Vintage 能力继续负责账户账龄语义，不把通用时间分组当作 Vintage。

验收：改变后续标签不会影响首标签结果；每个窗口分箱版本不变；无标签生产窗口能报告分布变化但不伪造监督性能；延迟标签回填可重算且保留版本。

## 批次四 端到端资源和部署治理

### D01 把现有资源策略贯通整个数据链路

**P2，L。** 复用 ParallelBudget、QueryStream、BinStatsAccumulator、Tuner retention 和已有报告缓存，不逐模块再发明独立资源参数。

- 新增大表推荐配置：读取 retain=False、有界并行消费、固定分箱增量聚合、按需保存中间结果。
- 报告提供可选择的缓存/行级数据保留策略与显式释放；保留当前完整模式以兼容交互式使用。
- 把数据源的完成/中断/失败状态传播给最终结果，避免将已消费的部分流误认为完整总体。
- 资源限制注明是预检、调度约束还是实际硬限制。先给出可读执行计划，再输出实际统计。

验收：流式和批量统计数值相同；主动中断/异常/下游停止消费都释放游标；不同窗口大小不改变行顺序和数值；大表轻量模式不随全部输入行数保留历史块；既有完整保留模式不丢失功能。

### D02 建立统一性能回归验收

**P2，M。** 整合 `tests/benchmarks` 与已有慢速并行测试。

基准至少覆盖：小表冷启动、宽表 EDA、数值/高基数混合编码、监督分箱、VIF/相关筛选、大规则集、多标签报告、大森林报告、完整 Excel 导出、百万级流式统计。

记录数据形状、dtype、随机种子、依赖真实版本、CPU/线程限制、串并行后端、预热策略、中位耗时、父子进程峰值 RSS、磁盘产物大小和结果哈希。性能比较在隔离进程进行，不能把功能测试并发期间的测量作为发布门槛。

验收：先达到语义等价再比较性能；在固定设备建立基线后才设置回归阈值；对低核机器有明确降级；不得靠静默跳过失败、减少图表或舍弃必要历史制造加速。

### D03 降低导入和部署依赖成本

**P2，M。** 先测量和调整导入，再根据用户兼容范围决定是否拆分依赖。

- 将全局样式/显示初始化变成显式设置或兼容开关，保留 Notebook 快捷体验。
- 对求解器、绘图、解释与数据库依赖按实际调用加载；继续保留便利顶层入口。
- 设计基础安装、推荐分析安装和完整安装的依赖集合；若拆 extras，保留迁移方式并在新版本清楚说明。
- CI 加入仅基础安装、单 extra、完整安装、构建后 wheel 安装的独立验证；依赖下限基于实际测试决定。

验收：轻量指标和推理入口不无故加载无关框架；缺失 optional dependency 时给出准确安装命令；使用已构建 wheel 的外部工作目录能运行关键入口；环境自检能识别分发元数据与实际导入版本不一致。

### D04 统一模型与规则的部署清单

**P2，M。** 在现有 artifact 格式和推理导出上补清单，原生模型、规则 JSON 和 PMML 仍保留各自能力边界。

清单应包含：模型/规则类型、字段顺序与 dtype、前处理/分箱/编码版本、类别映射、分数转换参数、输入输出 schema、依赖版本、是否含训练状态、是否可续训、制品摘要及验证记录。默认不把训练明细作为部署必要组成。

验收：原始特征输入经过导出制品后与训练态推理一致；列顺序改变可按契约对齐，缺列报错；缺失折文件明确失败；受支持格式在独立进程和目标环境验证；旧 artifact 的迁移和拒绝理由明确。

### D05 按职责拆解高耦合模块

**P2，L，安排在对应功能修改时逐步实施。** 优先拆出报告统计、章节编排、Excel 渲染和产物发布。`ReportResult` 及 `ArtifactTransaction` 的通用部分下沉到中立层，模型与 EDA 通过兼容导入路径使用。

验收：现有公开 import 路径、输出表和预测结果保持兼容；核心计算可以不启动绘图完成验证；拆分提交不混入统计公式变更；通过现有语义和报告契约测试。

## 批次五 候选新能力

这些能力暂不应优先于上述修复。每项先选择一个真实业务样例，证明需求、输入约束和验收方式后再实施。

| 候选能力 | 当前基础 | 新增价值 | 启动条件 |
| --- | --- | --- | --- |
| 按决策时点生成特征 | NumExprDerive、时间划分、数据库接入 | 时间窗口聚合、事件可见时间、as-of 对齐、防止未来特征进入历史样本 | 明确实体键、事件时间、可用时间、修订策略和真实样例 |
| 约束化原因码与反事实 | 已有 SHAP、reason codes、counterfactual | 区分可变/不可变特征，限制行动范围和联合可行性 | 业务提供可行动约束及可接受解释输出 |
| 模型与策略组合优化 | 业务损失、阈值、规则、Swap | 在审批/容量/金额风险限制下联合选择策略 | 已完成 C04 的可核对收益和预算口径 |
| 标签延迟下的持续评估 | Vintage、监控基准、时间报表 | 未成熟窗口跟踪、标签回填、监督指标版本化 | 有可靠观察截止与回填记录 |
| 拒绝样本推断或因果策略评估 | 逾期率预估、参考客群、策略比较 | 减少仅观察通过样本造成的偏差 | 能说明缺失机制并获得外部验证或受控试验；不可只凭推断后的训练分数验收 |

多分类、一般回归和更多神经网络不作为自动扩张方向。当前各能力的适用范围先写清楚；只有明确需求与独立验收样例存在时再扩展。

## 兼容与迁移原则

1. **先固定现有契约。** 从当前代码及真实用户调用建立兼容清单，不用过时文档作为唯一依据。
2. **错误配置尽早拒绝。** 拼错字段、概率越界、未消费参数无需继续返回表面正常结果；发布说明指出变化。
3. **业务默认值显式迁移。** 缺失标签归零、样本内编码、独立分箱、完整历史保留等旧行为先保留兼容选项；新推荐流程选择明确、安全且可审计的默认值。
4. **计算修复与重构分开。** 不把统计公式修复、模块搬迁、返回类型变化和性能优化塞进同一批交付。
5. **不改变无关工作区。** 本次仅新增报告与证据；后续按明确任务实施，不自动提交、建分支或发布。

## 每批通用验收要求

| 验收层 | 必须回答的问题 |
| --- | --- |
| 数值语义 | 分母、标签、正类、风险方向、权重、分箱、排序同分规则是否一致？ |
| 数据隔离 | 验证和未来标签是否影响训练产物？分组/时间约束是否真实生效？ |
| 失败语义 | 无效输入是否明确拒绝？部分结果和完整成功能否从机器结果区分？ |
| 可重现性 | 固定输入/配置/种子和制品往返是否保留预测及统计？ |
| 兼容性 | 既有 import、返回值、缺失策略和持久化格式如何保留或迁移？ |
| 资源行为 | 线程、进程、内存、缓存、磁盘和关闭操作是否在声明范围内？ |
| 报告交付 | 表格可重算，JSON 可解析，Excel 可打开，关键图表经过视觉检查？ |
| 文档样例 | 公共说明、Notebook、安装 extras 与当前实现一致？ |

测试优先采用有预期业务含义的最小反例、批量/流式等价、串行/并行等价和制品往返。不要只验证能执行、列数正确或文件存在。已有基础测试失败应单独归因，不能一律算作新修改引入，也不能用宽泛 skip 隐藏。

## 第一轮实施建议

首先处理 A00 的已复现兼容失败，并以小范围修复完成 A05 的字段/概率验证、A02 的未消费参数拒绝，以及 B03 的 JSON 表结构输出；同时锁定 A01/A03/A04 的目标契约和黄金样例。随后集中完成标签、权重、冻结分箱三项贯通，再推进划分与 OOF 推荐流程。

这一顺序能先关闭配置错误被忽略的入口，再处理影响面更大的业务口径变更。核心判断标准是：同一业务问题在不同 API、不同报告页面和不同执行方式下，是否能得到一致且可追溯的答案。
