## 二、P0 — 已确认的运行时 Bug（必须修复）

### P0-1. `style_bin_table` / `BinTableDisplay` 公开 API 直接抛 `NameError`
- **证据**：[hscredit/utils/bin_table_display.py:324-329](../hscredit/utils/bin_table_display.py#L324-L329)
  ```python
      return styler
      """查找匹配的列名（支持多级表头）."""   # ← def _find_columns(df, pattern) 行丢失
      if isinstance(df.columns, pd.MultiIndex):
          return [col for col in df.columns if pattern in str(col[1])]
      ...
  ```
  `def _find_columns(...)` 定义行丢失，函数体变成 `return styler` 之后的**不可达死代码**，故 `_find_columns` 从未定义；而 `style_bin_table` 在 [行 223/244/263](../hscredit/utils/bin_table_display.py#L223) 调用它。
- **实测复现**：`from hscredit.utils import style_bin_table; style_bin_table(df)` → `NameError: name '_find_columns' is not defined`。
- **根因**：`bin_table_display.py` 是 [pandas_extensions.py](../hscredit/utils/pandas_extensions.py) 的**遗留重复实现**。后者才是现行正确版本（定义了 `_find_columns@892`、`_style_bin_table@589`，`df.show()` 正常工作）。两者都在 `utils/__init__.py` 被导出（`style_bin_table`、`BinTableDisplay` 来自坏的那个）。
- **影响**：公开 API `style_bin_table` 完全不可用；`from hscredit.utils import BinTableDisplay` 同样走坏实现。
- **建议**：删除整个 `bin_table_display.py`（与近期删除 `report/mining/visualization.py` 重复模块的处理一致），`utils/__init__.py` 改为从 `pandas_extensions` 导出 `BinTableDisplay`，并在 `pandas_extensions` 暴露 `style_bin_table`（其内部 `_style_bin_table`）。

### P0-2. `RulesClassifier.get_feature_importances()` 抛 `NameError`
- **证据**：[hscredit/core/models/rules/rule_classifier.py:520](../hscredit/core/models/rules/rule_classifier.py#L520) 调用 `check_is_fitted(self)`，但该文件 import 段（行 11-18）**未导入** `check_is_fitted`。
- **影响**：调用 `get_feature_importances()` 即 `NameError`。
- **建议**：`from sklearn.utils.validation import check_is_fitted`，或改用项目统一的 `raise_not_fitted()` / `NotFittedError`。

## 三、P1 — 设计与一致性问题

### P1-3. `import hscredit` 急切加载全部可选重依赖（~4s）
- **证据**：`import hscredit` 后 `sys.modules` 含 `xgboost/lightgbm/catboost/optuna/shap/ngboost`，耗时约 4.03s。触发链（import 追踪）：
  - `xgboost` ← `core/models/boosting/xgboost_model.py:28`
  - `catboost` ← `core/models/boosting/catboost_model.py:26`
  - `shap` ← `core/models/evaluation/interpretability.py:44`
  - `optuna` ← `core/models/tuning/tuning.py:85`
- **现状**：各模块有 `try/except ImportError` + `*_AVAILABLE` 守卫，故**缺失不会崩溃**；但已安装时由 `hscredit/__init__` 的 `from .core.models import *` 链式急切加载，违背 CLAUDE.md「可选依赖懒加载」的设计意图，且拖慢导入。
- **建议**：用 PEP 562 模块级 `__getattr__` 懒加载，或在 `core/models/__init__` 延迟导入 boosting/tuning/evaluation 子模块。

### P1-4. 「未拟合」异常类型不统一
- **证据**：19 个分箱器用 `raise ValueError("分箱器尚未拟合")`（best_iv/best_ks/best_lift/cart/chi_merge/cp_sat/genetic/kernel_density/kmeans/mdlp/monotonic/optimal×2/or/quantile/smooth/target_bad_rate/tree/uniform），仅 5 处用 `NotFittedError`/`HSCreditError`。
- **冲突**：CLAUDE.md 规定所有自定义异常继承 `HSCreditError`，未拟合应用 `NotFittedError`/`raise_not_fitted()`。
- **影响**：用户无法用 `except NotFittedError` 统一捕获未拟合状态。
- **建议**：统一替换为 `raise_not_fitted()`。

### P1-5. `feature_summary` 名称冲突 → 静默遮蔽
- **证据**：`core.metrics.feature.feature_summary` 与 `core.eda.overview.feature_summary` 是**两个不同函数**；因 `hscredit/__init__` 星号导入顺序（eda 在 metrics 之后），`hscredit.feature_summary` 静默解析为 **eda 版本**，metrics 版本被遮蔽（实测 `a is b == False`）。
- **根因**：顶层大量 `from ... import *`（共 325 个公开名）。
- **建议**：去掉 core.metrics.feature 中的 feature_summary 方法

## 四、P1 — 打包与配置问题

> 与此前「打包/编译完善」诉求直接相关。

### P1-6. `package-data` 路径错误 + `py.typed` 缺失
- **证据**：[pyproject.toml:119-120](../pyproject.toml#L119-L120)
  ```toml
  [tool.setuptools.package-data]
  hscredit = ["py.typed", "report/excel/*.xlsx", "**/*.json", "**/*.yaml", "**/*.yml"]
  ```
  - `hscredit/py.typed` **不存在**（声明了 typed 包但 PEP 561 实际未生效）。
  - `hscredit/report/excel/` 目录**不存在**。真实资源在 `hscredit/resources/{datasets/germancredit.csv, fonts/font.ttf, templates/template.xlsx}`，且运行时被 `excel/writer.py:107`、`utils/datasets.py:27`、`utils/init.py:41` 加载。
  - `**/*.json|yaml|yml` 在仓库中无匹配文件。
- **缓解**：`include-package-data=true` + `MANIFEST.in` 的 `recursive-include hscredit *.xlsx *.csv *.ttf` 使 **sdist** 仍带上资源；但 package-data 显式 glob 误导，且对 wheel 不够稳妥。
- **建议**：改为 `hscredit = ["py.typed", "resources/**/*"]`，并创建空的 `hscredit/py.typed`（若确实要提供类型）或删除该项。

### P1-7. pytest 配置重复且冲突
- **证据**：根目录同时有 `pytest.ini` 与 `pyproject.toml [tool.pytest.ini_options]`，运行时 pytest 提示 `ignoring pytest config in pyproject.toml`。两者内容不一致（`markers`、`filterwarnings`、`pythonpath` 仅在 pytest.ini）。
- **影响**：pyproject 的 pytest 配置实际不生效，易误导。
- **建议**：二选一（保留 pytest.ini，删除 pyproject 中的 `[tool.pytest.ini_options]`；或反之并补齐 markers）。

### P1-10. Python 版本支持矩阵不自洽
- `requires-python=">=3.8"`，classifiers 与 black target 列到 3.14；但 `numpy>=1.19`/`pandas>=1.2` 无法在 3.13/3.14 安装，且 3.8 已 EOL（当前测试环境为 3.14）。
- **建议**：收敛为实际支持区间（如 3.9–3.14）并同步下限版本。

### P1-11. `requirements.txt` 与 extras 不同步
- 自称「全量环境」却缺 `torch`/`pytorch-tabnet`（`net` extra）。建议以 `pip install -e ".[all]"` 为准，或补齐保持一致。

## 五、P2 — 健壮性与代码卫生

- **建议**：脚本式测试改写为带 assert 的真实用例；为 P0-1、P0-2 增加回归测试。

## 七、测试健康现状（本次抽样）

- 共收集 **455** 个测试。
- `tests/test_reports/` + `tests/test_rules/`：**67 passed**、1 skipped、**1 failed**（`test_excel_writer.py::test_insert_picture_row_span_uses_ceil`，`assert 8 == 10`，既有逻辑失败）。
- `tests/test_utils/`：**13 passed**。
- `tests/test_encoding/test_gbm_encoder_missing.py`：**1 failed / 5 passed** —— `TypeError: check_X_y() got an unexpected keyword argument 'force_all_finite'`。
  - **性质**：上游版本不兼容。新版 scikit-learn 将 `force_all_finite` 改名为 `ensure_all_finite`，安装的 `lightgbm` 仍传旧参数 → 在 `gbm_encoder._fit_lightgbm` 链路上抛错。**非 hscredit 逻辑 bug**，由 P1-10「版本矩阵不受约束」（Py 3.14 + 前沿 sklearn + 旧 lightgbm）暴露。
  - **建议**：在受支持的版本区间内固定 `scikit-learn`/`lightgbm` 兼容下限上限；或在 `LightGBMRiskModel.fit` 处对该参数差异做适配。
- 全量套件含模型训练/Optuna，单次 280s 未跑完（约 41% 处被 timeout 截断，慢测试集中在后段）；建议 CI 分层：`-m "not slow and not integration"` 作快速门禁 + 定时全量。
