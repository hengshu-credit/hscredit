## 1. 本轮采用的明确口径

| 情况 | 结果 | 原因 |
|---|---|---|
| 单类标签或某类金额为 0 | 分箱 KS 为 0，统计口径标明单类/无有效类别 | 与现有 `ks()` 和分箱搜索内核一致；这个 0 是兼容值，不是模型有效性的证据 |
| 全部拒绝、总体为空、总体坏率为 0 | 坏账改善为 NaN | 没有剩余人群或没有相对变化的分母 |
| 拒绝占比为 0 | 风险拒绝比为 NaN | 没有可定义的“每单位拒绝效率” |
| 数值为 NaN 的报告指标 | Excel 显示为空；执行状态页说明“不适用” | 不把未定义伪装成 0、100% 或文本 `nan` |
| 合计行 | 各特征、各长表标签分别汇总；重复调用不重复计数 | 多个特征/标签是对同一批样本的不同视图 |
| TOP 人群坏账改善 | `(总体坏率－拒绝 TOP 后剩余坏率)/总体坏率` | 与分箱和规则的拒绝改善相同，不再误用 `LIFT−1` |
| WOE 截断 | 既有 IV 列继续表示截断后的实际编码信息量，另列原始 WOE/IV | 避免静默改变算法评价口径，同时提供完整对照 |
| 连续目标含负数或没有正总量 | 均值、总和、方差等统计保留；贡献占比、LIFT、贡献 KS 为 NaN | 这些目标无法构成非负贡献分布 |

拒绝改善的边界展示曾作为可选问题征询。未收到回复后采用已说明的推荐方案：空值并披露不适用原因。其余已有明确文档定义的口径保持原设计。

## 3. 本轮额外确认并修复的错误

| 编号 | 修复前的独立复现 | 修复后的行为 |
|---|---|---|
| R01 金额 KS 依赖计量单位 | 完美分离的金额都缩为 `1e-12` 时，KS 从约 1 变为 0.019607843 | KS 不使用分母 epsilon；同一分布的币种/单位缩放不改变 KS |
| R02 多特征合计重复人群 | 8 人分析两个特征，末尾出现一个“16 人”合计 | 每个特征各有 8 人合计 |
| R03 长表重复合计混合标签 | 原有“短期 4 人、长期 4 人”再次合计变为“短期 8 人” | 按特征与标签组合分组，重复合计保持原结果 |
| R04 先筛选列导致合计坏率丢失 | `return_cols=['坏样本率']` 去掉了用于合计的计数，合计坏率变成 NaN | 先完整聚合，再选择输出列 |
| R05 提前舍入造成金额合计比例失真 | 小额金额按箱舍入后再求合计，好坏金额可能变成 0 | 合计使用原始数值，展示层最后舍入 |
| R06 规则内部字段碰撞 | 金额列叫 `target` 时，命中金额应为 10、坏率 10%，却输出 1、100% | 标签、金额、命中掩码分开保存；不覆盖原始特征 |
| R07 模型 TOP 改善算成 LIFT−1 | 8 人中坏客户均在 TOP 25%，拒绝后无坏客户，旧表显示改善 300% | 输出正确的 100%；TOP 100% 无剩余人群时为空 |
| R08 零金额回退件数坏率 | 金额全部为 0 的 TOP 表混入件数坏率，出现 0/-100% 等假结果 | 金额指标为空，不替换为另一统计口径 |
| R09 规则掩码整型索引 | 0/1 整数掩码被 NumPy 当成行号索引 | 校验并规范为布尔掩码；非法掩码拒绝计算 |
| R10 评分卡摘要故障被吞掉 | `summary()` 抛错后仍能把报告标成完整 | 故障进入 ReportResult，strict 阻止发布；不支持线性系数的模型则标为“不适用” |
| R11 空通过人群仍报风险改善 | 两种 Swap 入口全部拒绝后均把新坏率写成 0 | 新坏率及派生风险变化为空，并可空白导出 |
| R12 Swap 汇总基准误用新通过人群 | 没有 out-out 人群时，全量基准退化为 new_pass；新通过人群的 LIFT/改善被错误归零或归一 | 总体基准从四类互斥客群的总量与坏量计算 |
| R13 连续目标伪造贡献指标 | 全零或含负数目标仍输出有效贡献占比/KS，零目标可显示 -100% 贡献改善 | 保留普通统计矩；贡献分布指标明确为不适用 |
| R14 多标签规则并行复制宽表 | 96,000 行、3 标签基准中，串行中位 0.305714 秒、并行 0.488480 秒，违反原 5% 开销门槛 | 标准表达式规则只向任务传递必要字段；独立复测串行 0.166242 秒、并行 0.113556 秒，1.464 倍加速；自定义规则保留完整输入 |
| R15 内存工作簿未规范缺失值 | 串/并行的内存单元格均为 NaN，但不相等；`pd.NA` 直接写入还会报错。保存后的 NaN 原本会变为空，因此不能称为已保存文件的数值不一致 | 普通/快速写入在设置单元格前将标量缺失规范为 None，内存状态和保存结果都为空 |
| R16 训练/测试坏率差误用 LIFT 差 | 命中坏率为 0.5 和 1 时，`badrate_diff` 返回 +0.666667，正确值应为 -0.5；真实数据 600/370 划分同样复现 | 改为训练命中坏率减测试命中坏率，任一命中人群为空则 NaN；该差值不是 PSI |

Swap 汇总表中的“风险改善”与流水线行级“坏账改善”沿用**当前客群相对全量的比较**语义，不将它们偷偷改成“移除当前客群”。结果 `attrs['统计口径']` 已说明其基准和分母；新旧策略通过人群的风险变化另行处理。

```python
# 需要继续聚合/排序/对账时保留原始精度

# 结果表带有口径，结构化报告的执行状态页也会包含说明

```

- 旧代码若断言“全拒绝改善为 1、无拒绝效率为 0”，应改为判断 NaN。
- 金额合计基于原始数据。因此，总体舍入值可能与“逐箱先舍入再相加”相差末位；后者不用于计算总体比例。
- `woe_clip` 非空时增加三列原始指标。原有列名及其截断后含义保留。
- `RuleMetrics` 的件数与金额字段继续分开，金额不会改写分类计数。
