# rule_swap_analysis 流水线修复设计

## 目标

修复 `rule_swap_analysis` 的阶段样本集合、规则集执行、生产通过率校准、实际与预测风险混合、金额口径、多标签及汇总结果，使报告能够准确表达“基础生产规则过滤 → 本次置出 → 不置入 → 本次置入”的逐步变化。

## 业务数据流

设输入分析样本为 `S0`。输入样本可以是生产全量进件，也可以是有偏通过样本。

1. `rules_base` 在 `S0` 上执行，命中并集为 `OUT-OUT`，基础规则后剩余样本为 `S1 = S0 - OUT-OUT`。基础规则是已有生产策略，不属于本次策略修改。
2. `rules_out` 在 `S1` 上执行，命中并集为 `IN-OUT`，本次置出后的 total 通过样本为 `S2 = S1 - IN-OUT`。
3. `rules_in` 在 `S2` 上执行，命中并集为 `OUT-IN`。不置入时的通过样本为 `IN-IN = S2 - OUT-IN`。
4. 置入后的通过样本为 `ALL-IN = IN-IN + OUT-IN = S2`。

所有原子客群必须互斥，且满足：

```text
S0 = OUT-OUT + IN-OUT + IN-IN + OUT-IN
S1 = IN-OUT + IN-IN + OUT-IN
S2 = IN-IN + OUT-IN = ALL-IN
```

## 规则集内部执行模式

### independent

每条规则都在该阶段的固定母集上执行。单规则明细允许重叠；阶段合计使用所有规则命中掩码的并集去重。只有合计结果能够推动到下一阶段。

### sequential

第一条规则在阶段母集上执行，后续规则依次在前一条规则剔除后的剩余样本上执行。各规则有效命中天然互斥；阶段合计等于各规则有效命中的并集与数量之和。

## 生产通过率校准

`sample_survival_rate` 表示输入分析样本 `S0` 对应的生产通过率，要求 `0 < sample_survival_rate <= 1`。

设输入样本数为 `N0`，某阶段状态样本数为 `Ns`：

```python
生产通过率 = sample_survival_rate * Ns / N0
绝对变化 = 当前阶段生产通过率 - 上一阶段生产通过率
相对变化 = 绝对变化 / 上一阶段生产通过率
```

计算不得通过 `int(N0 / sample_survival_rate)` 构造虚拟生产样本数，避免取整误差。

报告区分：

- `样本占比`：当前行样本数除以输入分析样本数。
- `阶段前生产通过率`：当前规则或阶段执行前的生产通过率。
- `生产通过率`：当前规则或阶段执行后的生产通过率。
- `通过率变化`：生产通过率的百分点变化。
- `通过率(相对值)`：相对上一阶段生产通过率的变化比例。

独立模式的规则明细基于相同阶段母集计算假设影响，不允许在相邻明细行之间做 `diff()`；阶段合计使用去重并集计算真实阶段变化。

## 风险来源与风险上浮

四个原子客群的默认风险来源为：

| 客群 | 风险来源 | 默认上浮 |
|---|---|---:|
| OUT-OUT | 实际 `y` | 1.0 |
| IN-OUT | 实际 `y` | 1.0 |
| IN-IN | 实际 `y` | 1.0 |
| OUT-IN | 评分分箱预测坏概率 | `out_in_uplift` |

OUT-IN 被视为无表现客群，即使输入数据存在该客群的 `y`，风险决策口径仍使用评分分箱预测概率。除 OUT-IN 外的客群必须具有有效 `y`；缺失时使用中文校验错误终止，禁止静默当作好样本。

每个样本先形成原始风险：有表现原子客群取 `y`，OUT-IN 取评分分箱预测概率；再按原子客群上浮系数形成调整后风险。任何阶段快照或合计行均通过汇总其原子客群风险计算，因此能够自然得到实际、预测或混合风险口径。

`swap_result` 比较：

```text
变化前 = IN-IN（不置入）
变化后 = ALL-IN（IN-IN + OUT-IN）
```

变化后调整坏样本数为 `IN-IN实际坏样本数 + OUT-IN预测坏样本数 × OUT-IN上浮系数`。

## 公开参数兼容

保留现有公开参数和返回键，新增：

```python
risk_uplifts: Optional[Dict[str, float]] = None
```

有效键为 `out_out`、`in_out`、`in_in`、`out_in`。默认系数为：

```python
{
    "out_out": 1.0,
    "in_out": 1.0,
    "in_in": 1.0,
    "out_in": out_in_uplift,
}
```

`risk_uplifts` 对应键覆盖默认值。所有系数必须为有限且非负数。上浮只作用于原子客群，阶段合计通过调整后坏样本数加权汇总，禁止对聚合坏样本率再次乘系数。

保留 `out_in_uplift` 以兼容现有调用。保留 `out_in_amount_fill` 与 `out_in_amount_col`，并真正用于 OUT-IN 缺失金额填充；字段值优先于定值。

## 目标变量与多标签

支持：

- 单目标 `target`。
- `overdue` 与 `dpds` 的笛卡尔积，标签名格式为 `{overdue}_{dpd}+`，坏样本定义为逾期天数严格大于 DPD。

单目标时保持当前单层列结构。多目标时：

- 样本集合、阶段及通过率列放在 MultiIndex 顶层 `分箱详情`。
- 每个目标标签作为一个顶层分组，包含原始和调整后的好坏样本数、坏样本率、LIFT、坏账改善及风险来源。
- `swap_result` 使用长表结构，增加 `目标标签` 列，每个标签分别输出通过率、逾期率、风险上浮和样本幸存比例。

评分分箱预测必须显式选择对应目标的坏样本率列，不允许在多标签表中回退到第一列。

## 金额口径

订单和金额统计使用同一套原子客群掩码与风险来源：

- 有表现客群坏样本金额为 `金额 × y`。
- OUT-IN坏样本金额为 `有效金额 × 预测坏概率 × 上浮系数`。
- OUT-IN有效金额优先使用 `out_in_amount_col` 的非缺失值，其次使用原 `amount`，最后使用 `out_in_amount_fill`。

金额字段存在时，报告保留订单口径字段，并新增 `样本总额`、`原始坏样本总额`、`调整后坏样本总额`、`原始坏样本率(金额)`、`调整后坏样本率(金额)`、`金额占比`；不得把金额写入 `样本总数`。

生产通过率默认仍按订单数和 `sample_survival_rate` 校准。金额占比只表达输入分析样本内部的金额占比，不冒充生产金额通过率。

## 分箱映射

优先复用 `feature_bin_stats` 生成的标准分箱信息。预测映射至少满足：

- 单箱 `[-inf, +inf)` 使用该箱坏样本率，不能返回零。
- 同时兼容 `分箱标签` 与旧列名 `分箱`。
- 多标签显式选择目标坏样本率列。
- 缺失评分使用缺失箱坏样本率；没有缺失箱时回退到非缺失总体坏样本率并标记风险来源，不能把缺失评分当好样本。
- 调用方提供的 `bin_table` 字典键必须与 `score` 映射键完全一致。
- 多评分权重必须有限、非负且总和大于零。

## 输出流水线

流水线按以下顺序展示存在的模块：

1. 全量样本状态。
2. OUT-OUT规则明细、OUT-OUT合计、基础规则后剩余样本。
3. IN-OUT规则明细、IN-OUT合计、total通过样本。
4. IN-IN不置入状态。
5. OUT-IN规则明细、OUT-IN合计、ALL-IN置入后状态。

新增 `行类型`，取值为 `状态`、`规则明细`、`阶段合计`。`reverse_order` 只改变最终展示顺序，所有业务指标和 `swap_result` 必须在反转前完成，确保结果不受展示参数影响。

## 校验与错误处理

- 至少一个规则集非空。
- `data` 必须包含评分、规则及金额配置所需字段。
- `sample_survival_rate` 必须位于 `(0, 1]`。
- `out_in_uplift` 和 `risk_uplifts` 必须有限且非负。
- 多评分映射、分箱表和权重键必须完全一致。
- 非 OUT-IN客群的实际标签不得缺失。
- 所有用户可见错误使用中文，并优先使用项目异常类型。

## 测试与验收

使用可手算小样本和 `examples/hscredit_yyp.xlsx` 验证：

1. 四原子客群互斥、完备及集合守恒。
2. independent 明细可重叠但合计去重；sequential 明细互斥且顺序漏斗。
3. OUT-IN母集为本次置出后的 total通过样本。
4. IN-IN、OUT-IN、ALL-IN样本数及通过率变化正确。
5. `sample_survival_rate=0.7` 时输入行生产通过率精确为70%。
6. 非 OUT-IN使用实际 `y`，OUT-IN使用预测并上浮；自定义分组上浮生效。
7. `reverse_order` 和 independent 规则顺序不改变 `swap_result`。
8. 金额仍保留订单样本数，并正确计算实际/预测混合坏样本金额。
9. 多标签分别输出非零且正确的风险指标。
10. 单箱、旧分箱列名、缺失评分及多评分键校验正确。
11. 现有并行串行一致性与失败传播测试继续通过。
